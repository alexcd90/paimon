## 本次进展亮点

### 1. Lumina 向量索引支持 Flink 增量构建

Lumina 向量索引此前每次构建都需要全量重建，对于持续写入的表代价极高。本次新增 `maxIndexedRowId` 参数，构建任务会自动跳过已索引的行范围，只处理新增数据对应的 shard，大幅降低资源消耗，适合实时向量检索场景。

**使用示例（调用增量构建 API）**：
```java
// 全量构建（原有行为，maxIndexedRowId = -1）
GenericIndexTopoBuilder.buildIndexAndExecute(
    env, table, "embedding", "LUMINA",
    partitionPredicate, options,
    GenericIndexTopoBuilder.NO_MAX_INDEXED_ROW_ID  // -1L
);

// 增量构建：跳过已索引的 row_id <= 199 的数据
GenericIndexTopoBuilder.buildIndexAndExecute(
    env, table, "embedding", "LUMINA",
    partitionPredicate, options,
    199L  // maxIndexedRowId：上次已索引到的最大 row_id
);
```

### 2. scan.primary-branch 允许主分支为 Append-Only 表

`scan.primary-branch` 用于多分支混读场景：指定的 primary-branch 分区数据优先，主表分区作为兜底 fallback。此前要求两个分支必须都是主键表，限制了 Append-Only 分支的使用。本次移除该限制，primary-branch 现在可以是 Append-Only 表，与 `scan.fallback-branch` 的语义完全对称。

**使用示例（Flink SQL）**：
```sql
-- 创建 Append-Only 表，并建立分支
CREATE TABLE t (pt INT NOT NULL, k INT NOT NULL, v STRING)
    PARTITIONED BY (pt) WITH ('bucket' = '-1');

CALL sys.create_branch('default.t', 'nb');

-- 将主表升级为主键表，分支保持 Append-Only
ALTER TABLE t SET ('primary-key' = 'pt, k', 'bucket' = '2');

-- 配置 primary-branch，读取时优先取 nb 分支数据
ALTER TABLE t SET ('scan.primary-branch' = 'nb');

-- 向各分支写入数据
INSERT INTO `t$branch_nb` VALUES (1, 20, 'cat'), (1, 30, 'dog');
INSERT INTO t VALUES (1, 10, 'apple'), (2, 10, 'horse');

-- 查询：pt=1 优先来自 nb 分支，pt=2 来自主表 fallback
SELECT v, k FROM t;
-- 结果: cat/20, dog/30, horse/10
```

### 3. Blob 表 ALTER TABLE + Compaction 后读取修复

Blob 表在执行 `ALTER TABLE SET` 变更属性后再触发 Compaction，随后读取会抛出 `All files in this bunch should have the same schema id` 异常。根因是 blob 文件跨 schema 版本后 schemaId 不一致，但 blob 文件本身不依赖 schema 演进。本次修复跳过 blob 文件的 schemaId 校验，同时禁止对 blob 列执行 RENAME 操作。

**触发场景复现与修复后验证**：
```sql
-- 创建含 blob 列的表
CREATE TABLE blob_t (
    id INT PRIMARY KEY NOT ENFORCED,
    content BYTES  -- blob 列
) WITH ('file.format' = 'avro');

-- 插入数据
INSERT INTO blob_t VALUES (1, ENCODE('hello', 'UTF-8'));

-- 修改表属性（触发 schema id 变更）
ALTER TABLE blob_t SET ('compaction.max.file-num' = '3');

-- 触发 Compaction
CALL sys.compact('default.blob_t');

-- 修复前：此处会抛出 IllegalArgumentException
-- 修复后：正常读取
SELECT id, DECODE(content, 'UTF-8') FROM blob_t;

-- blob 列不允许 rename（修复后会明确报错提示）
-- ALTER TABLE blob_t RENAME COLUMN content TO data;
-- 报错: Cannot rename BLOB column: [content]
```

### 4. Spark SHOW TABLE EXTENDED PARTITION 支持分区统计

`SHOW TABLE EXTENDED` 是排查分区数据规模的常用命令，此前 Paimon 表的该命令不返回分区统计信息（行数、文件大小等）。本次补全了 `Partition Parameters` 和 `Partition Statistics` 两个字段，方便直接在 Spark SQL 中查看分区数据量。

**使用示例（Spark SQL）**：
```sql
-- 查看指定分区的统计信息
SHOW TABLE EXTENDED IN my_db LIKE 'my_table' PARTITION(dt = '2024-01-01');

-- 输出的 information 字段中将包含：
-- Partition Values:     [dt=2024-01-01]
-- Partition Parameters: {recordCount=100000, fileSizeInBytes=52428800, fileCount=5, lastFileCreationTime=...}
-- Partition Statistics: 100000 rows, 52428800 bytes
```

### 5. Flink StreamExecutionEnvironment 版本兼容性修复

Flink 1.x 和 2.x 在 `StreamExecutionEnvironment` 的内部 API 上存在差异，导致 BTree 索引和 Lumina 索引的拓扑构建在部分 Flink 版本下抛出 `NoSuchMethodError`。本次提取 `StreamExecutionEnvironmentUtils` 工具类，为 flink1 / flink2 模块分别提供适配实现，无需用户感知版本差异。

**影响范围**：使用 `paimon-flink-action` 执行以下操作时自动生效：
```bash
# 构建 BTree 全局索引
flink run paimon-flink-action.jar build_index \
    --warehouse hdfs://nn/warehouse \
    --database mydb --table mytable \
    --index_type BTREE

# 构建 Lumina 向量索引
flink run paimon-flink-action.jar build_index \
    --warehouse hdfs://nn/warehouse \
    --database mydb --table mytable \
    --index_type LUMINA --index_column embedding
```
